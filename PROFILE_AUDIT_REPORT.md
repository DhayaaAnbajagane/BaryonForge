# BaryonForge Profile Class and Documentation Audit

## Scope and method

- Checkout: `check-debug`, based on clean-main revision `fafc0f31f68a1b8a6da791afdf76a686b4473cf0`.
- Scope: all 93 top-level classes in the 10 profile modules below; README and docs quickstart; generated API configuration; and relevant notebook call patterns.
- Inventory by module: Arico20 21; BaryonCorrection 3; Base 1; Battaglia 3; HyDif 4; Mead20 20; Schneider19 10; Schneider25 11; Thermodynamic 12; misc 8.
- I compared runtime class docstrings, signatures/defaults, inheritance/compositions, equations, boundaries, units, and `__all__` exposure. Notebooks were inspected but not executed; no remote data was downloaded. No tests were added.
- The math corrections align docs with code; they do not independently validate a model against its paper. No scientific-validity claim was independently checked against literature.
- The earlier runtime-debug work remains preserved in `BaryonForge/utils/Tabulate.py` and `DEBUG_REPORT.md`.

|---|---|---|

| F2 | `Schneider19.DarkMatter` doc used `[1+r/r_t]^-2`; code uses `[1+(r/r_t)^2]^-2`. | Corrected. |
| F3 | `Schneider19.Gas` doc omitted `v^gamma` in the outer GNFW factor and reversed the roles of `delta` and `gamma`. | Corrected the equation and slope descriptions. |
| F4 | `Schneider19.CollisionlessMatter` described a different relaxation mass sum/update than code. | Documented the iterative `M_f`, `zeta` update, and final normalized cumulative mass relation. |
| F5 | Hydrostatic pressure integral docs had the wrong sign; Thermodynamic `Temperature` had malformed `P(r)` math. | Corrected both; Pressure example now uses public `.real()`. |
| F6 | `ThermalSZ` described physical line-of-sight units without stating its raw projected result remains `a^2 y_phys`. | Clarified the physical-y equation and the `ComovingToPhysical(factor=-3)` wrapper behavior. |
| F7 | Arico helper docs used `z` despite `a, cosmo` signatures; `Temperature` claimed a default `BoundGas` although code uses composite `Gas`; its pressure equation omitted the full-gas assignment. | Corrected helper names, default profile, projection description, and pressure composition. Added Arico Stars integration defaults. |
| F8 | Arico CLM docs copied S19's default dark matter and `r_max_int=1e5`; code defaults to `ModifiedDarkMatter` and `r_max_int=10`. Arico DMB docs copied S19 normalization/two-halo claims although it directly sums components. | Corrected Arico defaults and replaced the DMB docs; added SatelliteStars documentation. |
| F9 | Mead20 DMB notes claimed a two-halo term although its constructor sets `TwoHalo=Zeros()`. Mead20 `T0` docs omitted `alpha`, the `3/2`, and physical radius `aR`. | Corrected no-two-halo statement and temperature normalization/radius. |
| F10 | Mead20 `GasAddDiffuse` docs implied a Gaussian ejected-gas sum; code adds a k-independent `f_ej M` Fourier term. `PressureAddDiffuse` docs listed constructor args it does not accept. | Documented actual Fourier and pressure wrapper behavior; added DMBAddDiffuse class docs. | F11 | Battaglia Pressure `truncate` docs did not say it is `r/R_delta`; example called private `_real`. | Clarified dimensionless cutoff and changed example to public `.real()`. |
| F12 | `misc.Truncation` docs named `epsilon` and hard-coded R200c; constructor is `epsilon_trunc` and code follows `mass_def`. | Corrected parameter and radius definitions. |
| F13 | BaseBFG docs omitted integration/cutoff defaults and implied that `cutoff=None` universally disables the real-space cutoff, although many profiles apply a numerical soft-cutoff value. | Added bounds and sample defaults; documented the numeric `1e3` comoving-Mpc cutoff and separated it from the independently configurable projection cutoff. |
| F14 | README/Sphinx quickstarts used `cosmo_dict` before definition and `...,` after keyword arguments, which fails Python parsing. | Defined cosmology first, supplied syntactically valid replaceable data placeholders, loaded source-tree model defaults, and made both examples compile. |
| C1 | Before the fix, direct identity checks showed that supplied outer gas was not used by default CLM construction in S19, S25, and Arico20. S25 additionally needs its combined `Gas` split into the CLM's `HotGas` and `InnerGas` inputs. | Fixed: default CLMs receive deep copies only of explicitly supplied components, leaving unspecified components at their legacy CLM defaults and avoiding cutoff mutation of caller profiles. S25 auto-splits only exact built-in `Gas` with exact `CombinedProfile(add, reflect=False, HotGas, InnerGas)` operands and no instance-level readout/method overrides. Subclasses or modified compositions require explicit CLM. Explicit CLM remains authoritative. Direct checks confirmed copied component values/shapes, caller cutoff preservation, rejection/override paths, and exact default DMB outputs against the legacy-default-CLM control. |
| C2 | `Arico20.DarkMatterBaryonwithLSS.__init__` accepted `darkmatter` but previously did not use it. | Fixed: a supplied darkmatter profile is copied into the generated default CLM; supplying it alongside explicit `collisionlessmatter` now raises `ValueError`. Direct checks covered ordinary and `ModifiedDarkMatter` inputs. The latter's bound-gas dependency is documented: pass a custom `ModifiedDarkMatter(gas=...)` through `darkmatter`, or construct the complete CLM explicitly. |
| C3 | The Sphinx hook previously copied `../../../latest` over a separate `BaryonForge` path before generating API pages; it failed in this checkout and could target another checkout if that external directory existed. | Replaced the external copy with a local package path derived from `conf.py`; the basic-theme HTML build now completes. Default `sphinx_rtd_theme` is not installed, offline intersphinx inventories cannot be fetched, and the Sphinx Python 3.8 environment lacks `pyccl`, so autodoc emitted import warnings. Generated API `.rst` files were removed after validation. |
| F15 | `Schneider25.InnerGas` defines a finite inner branch `h**3`, but evaluating the outer `r**-3` branch at `r=0` produced `0 * inf = NaN`. For extremely small positive radii the taper can round to zero and produce the same NaN. | The taper is set to its exact central limit and the outer branch uses a finite radius wherever its weight is zero. Both `r=0` and radii down to `1e-200` now return the finite inner limit without runtime warnings. |
| F16 | `Mead20.BoundGas` and `Mead20.Temperature` evaluate `log(1+x)/x` directly; at `x=0` this computes `0/0`, although the ratio's limit is 1 (and `T(0)=T0`). Direct probes returned NaN with runtime warnings. | Both readouts now use `log1p` and masked division with output 1 at zero. Their docstrings state the finite central limits. |
| F17 | `Arico20.BoundGasDeprecated` has the same removable `log(1+x)/x` limit and returned NaN at the origin. `BoundGasUntruncated` returned a finite core value, but eagerly evaluating its unselected NFW tail divided by zero and emitted a runtime warning. | The deprecated profile now evaluates the central ratio as 1 and keeps the unselected tail denominator finite. The untruncated profile likewise uses a finite denominator for the unused NFW branch at zero; its selected core output is unchanged. |
| F18 | `BaryonificationClass.displacement()` and its batched runner readout took `log(0)`, yielding NaN for a regular radial mapping whose analytic central displacement is zero. | Zero radii now use a safe interpolation coordinate and return exactly zero in both scalar/vector and batched paths; the zero point is excluded from out-of-table warnings. |
| F19 | `_warn_outside_table()` reconstructed radius bounds with `exp(log(bound))`; at an exact `R_min=0.05` this rounded to `0.05000000000000001` and emitted a false outside-range warning. The toy inward map also confirms that the mapped final radius can fall below the sampled grid and is then zero-filled. | Endpoint comparisons now tolerate a few ulps. The existing zero-fill for mapped radii outside the table is retained and documented: choose the radial table interval to cover both the initial and mapped radii, rather than relying on unsupported extrapolation. |
| F20 | `Thermodynamic.GasNumberDensity._real()` called the supplied profile's private `_real()` method. A profile whose public `real()` applies a factor of 3 consequently produced one third of the documented public-profile result. | The wrapper now calls `Gas.real()`; the projected path already used `Gas.projected()`. The direct custom-profile probe now matches the public real/projected APIs. |
| F21 | Hydrostatic pressure interpolated in `log(r)` with `extrapolate=False`; `r=0` and all radii below `r_min_int` became NaN and were replaced by zero, despite the finite central pressure at the first integration node. Temperature and tSZ inherited the zero. | Nonnegative radii below the first integration node now use the first sampled pressure value. The docstring records this numerical lower-grid limit; direct pressure/temperature/tSZ/X-ray checks are finite and warning-free at the center. |
| F22 | The Arico20 and Green20 non-thermal fraction formulae contain `(x/e)**f` with `f < 0`; at `x=0` this gave a finite analytic limit but emitted a divide-by-zero warning. | The zero-radius power is evaluated using its limit `+inf`, making the exponent zero without a runtime warning. Derived Arico20 thermal-pressure and temperature paths remain finite. |
| F23 | `Schneider19.ShockedGas` evaluates `log(r)` in its shock taper. The finite small-radius taper is 1, but a zero-radius query emitted a divide-by-zero warning. | The taper now uses its limiting factor 1 at `r=0` without evaluating `log(0)`. |
