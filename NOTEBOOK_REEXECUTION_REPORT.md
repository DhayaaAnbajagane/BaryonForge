## Material output differences

### Notebook 10: explicit gas passed into the CLM

Cells 15 and 18 pass `gas=Gas_S19(**tmp)` to `Schneider19.DarkMatterBaryon`. In clean-main commit `fafc0f31`, `DarkMatterBaryon` constructed its CLM as `CollisionlessMatter(**kwargs)`, which gave the CLM a default `Gas` profile. The current check-debug constructor forwards an explicitly supplied gas through `clm_components`, so the CLM now uses the same `Gas_S19` model as the outer DMB profile. This intentional profile-routing change explains the shifted displacement curves.

The controlled cell 15/18 comparison recomputed the five `M_c` and five `eta` parameter sweeps on identical cosmology and radius grids. Current-vs-main arrays have shape 5×4×100; maximum absolute differences are 0.04157 Mpc (`M_c`) and 0.04139 Mpc (`eta`). Large relative maxima occur near zero crossings. For the representative first `M_c` value, the direct CLM component profiles differ while the DMB gas and stars match; the CLM maximum relative difference is 6.24%. The DMO integrated masses match exactly. DMB normalization factors differ by less than 1e-9, and the normalized one-halo mass matches to floating precision, so the change redistributes the CLM profile without breaking mass conservation. The stored first cell 15 plot is closer to a clean-main rendering than the check-debug rendering (correlation 0.869 vs 0.729; mean pixel delta 4.03 vs 7.26).

### Notebook 12: stored displacement plots are stale relative to current computation

The rerun's input plot in cell 6 is pixel-identical to stored output, but the displacement sweep plots in cells 13, 16, 19, and 22 differ. These cells call `Arico20.DarkMatterBaryon(**tmp)` without explicit gas, stars, or CLM objects. In check-debug the conditional `clm_components` is empty and falls through to `CollisionlessMatter(**kwargs)`, the same call used by `fafc0f31`. The Arico20 DMB/CLM numerical bodies are unchanged. Other modified Arico20 and BaryonCorrection code adds origin guards or warning tolerance; the cell 13 control uses positive radii (`R >= 0.01 Mpc`, table `R_min=1e-4 Mpc`), so those changes do not affect its values. A direct comparison for the notebook's `M_c=1e13/h` cell 13 case, all four masses, and the 10,000-point `[0.01, 8] Mpc` grid produced bit-for-bit identical current and clean-main displacement arrays (shape 4×10,000; max absolute and relative difference 0). This supports stale embedded output from an older execution/dependency state. The other parameter sweeps use the same default profile construction but were not individually recomputed in the control.

### Notebook 22: C1 custom-gas routing explains the displacement shift

Cells 4 and 6 match stored PNGs exactly. Cell 8 passes `HyDif.Gas` as the explicit gas to `Schneider19.DarkMatterBaryon`, which is the same C1 path as notebook 10. A direct current-vs-clean-main control recomputed all three masses, three `f_comp` targets, and the notebook's 200-point radius grid. Its displacement arrays differ by up to 0.05990 Mpc; peak changes range from −37.8% to +9.8% across the nine combinations (the highest-mass, `f_comp=0.9` peak is +9.79%). DMO masses match exactly, normalization factors differ by at most 2.42e-9, and normalized one-halo masses agree within 0.03 Msun. This confirms the visible stored-to-new drift follows the intended CLM gas-routing update while preserving mass conservation.
